# 2026-07-13 公开版隐私规则细化：雇主内部信息与在职个人

`design/2026_07_13_fable5_prompt_tuning.md` 的同日后续。作者提出「章节不公开
的判断要不要更详细」，本次基于 2026-05 至 07 的历史日报与公开版实证，
细化了判定规则。

## 一、实证结论

### `[章节不公开]` 的历史使用（全部 5 次，均在 5 月）

| 日期 | 内容 | 类型 |
|---|---|---|
| 05/03 | AI 与职场格局（延伸到种族讨论） | 社会敏感议题 |
| 05/04 | 某大厂内部开放 Claude Code 的 rollout 政策 | 雇主内部政策 |
| 05/07 | 群友 YouTube 频道 10 万订阅幕后 | 可交叉识别真人 |
| 05/25 | 群里直播发可用 API key | 凭证泄露 |
| 05/29 | 民企员工交护照传闻 | 企业敏感政策/政治敏感 |

凭证泄露、政治/社会敏感、交叉识别三类判定稳定，无需改动。

### 系统性漏网的两类（均已原样发布到公开版）

1. **群友亲历自述的雇主内部非公开信息**：05/20 Meta 裁员具体赔偿方案、
   05/20 微软内部整治会议纪要（含具体人事件）、06/01 Copilot 内部 survey
   有同事被 warn、06/12 领导「两倍工资 token」内部指令。
2. **可唯一定位的第三方在职人员负面画像**：06/17「巡楼查考勤」director
   （原公司 + 职级 + 跳槽去向的组合基本唯一定位）。对照 06/04 考公培训 CEO
   被模糊化为「一位教育行业创始人」后发布——同类情形处理不一致，
   说明缺明确规则。

### 机制性发现

- **导读泄漏**：05/25 API key 章节正文被正确隐藏，但导读那句概述照进公开版。
  `[章节不公开]` 只剥 `###` 正文，此前无导读联动规则。
- **跨日聚合**：公开版身份（`/alias` 自选别名或稳定动物默认名）跨日稳定，
  同一别名多日披露可拼出「雇主 + 部门 + 内部政策」画像（06/01、06/12、
  06/17 三天即可拼合出一位微软员工的完整轮廓）。
- **旧规则的逃生口**：判定规则 1 里「500 人群发言已默认接受可识别性」
  被模型引用来放行雇主内幕（05/18 thinking 原话可证）——旧框架只问
  「可识别性」，不问「公开后的现实后果」（雇主追责、名誉损害）。

## 二、决策（作者拍板）

1. **雇主内部信息**：模糊化发言者与涉及的个人后照常公开；**大厂不模糊
   公司名**（员工数以万计，公司名定位不到个人），中小公司模糊公司名。
2. **不回顾清理**已发布的历史文章，新规则只管未来。
3. 群友吐槽自己老板等同类情形，同规则处理（模糊说话人，大厂留公司名）。

## 三、提示词落地（`prompts.py` SYSTEM_PROMPT「章节不公开」节）

- 新增「雇主内部信息与在职个人」专项规则：发言者写「某群友」不用 token；
  内部个人拆掉可定位细节组合；公司名按大厂/小厂分档；「后果测试」
  （当事人或雇主明天读到会不会惹麻烦）；结合 `<previous_reports>` 看累积
  披露从严；有公开出处的报道与标注未证实的传闻不受约束。
- 规则 1 的「500 人群可识别性豁免」加了排除条款，指向专项规则，
  堵住旧逃生口。
- 新增导读联动：被标不公开的章节，导读不得提及其内容。

### 已知取舍

「发言者写某群友」对群内版同样生效（extract.md 一份供两版渲染）——群内版
这类章节也会失去署名。可接受：群友本就看过原聊天。若日后想群内版保留署名，
需程序层方案（如 `token[公开匿称]` 标记由 renderer 只在公开版替换），
暂不做。

## 四、跨日聚合的结构性方案（讨论中，未定）

作者曾考虑：每日轮换公开昵称 / 取消 `/alias` 自定义昵称。当前建议是
**两者都不做**：

- 稳定人设是公开版可读性核心（连续剧人物、`[[ref:]]` 续写都依赖它）；
- 轮换防不住内容层面的重新串联，付出全部可读性只买到名义断链；
- 设 `/alias` 的群友是主动要公开人设的人，取消是惩罚想被看见的人；
- 危险处已由「敏感披露署名某群友」外科手术式切断。

若后续观察到「某群友」规则仍挡不住聚合，再回头评估轮换。
