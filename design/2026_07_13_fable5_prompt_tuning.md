# 2026-07-13 提示词 Fable 5 适配：拆数量档位、留红线

主模型已于 07/03 由 Opus 4.6 切换为 Fable 5（`e761a0c`），但 `prompts.py`
仍是为 Opus 4.6 调优的版本。本文记录一次基于 debug 历史的系统性复盘：
07/01–07/10 双模型输出并排对比 + 全部 Fable 5 thinking 记录的摩擦点分析，
以及据此对提示词的调整。未落地的程序层建议也记录在此，待后续实施。

## 一、证据：Fable 5 在旧提示词下的行为

### 输出对比（07/01、07/02 双版本 + 07/03 主对比对调后）

| 维度 | Opus 4.6 | Fable 5 |
|---|---|---|
| 全文长度 | 基线 | **+21%～+47%** |
| `###` 子话题数 | 16–19 | **21–26**（07/07 极端到 32） |
| 行内「」摘抄 | 49–54 处 | **57–108 处（约 2 倍）** |
| blockquote | 1–6 条 | 2–10 条（两者都远低于旧提示词的建议档位） |
| 专题抽取 | 保守，常不抽 | 几乎每天 1 个、偶尔 2 个，同素材更果断 |
| 格式合规（ref/tags/⟨⟩/命名） | 好 | 好（偶发 tag 用点号如 `glm-5.2`） |
| 长尾话题覆盖 | 偶有遗漏 | 更全（07/02 独有 4+ 条 Opus 未收话题） |

结论：旧提示词里大量**针对 Opus 压缩倾向的单向防守措辞**（「宁可多个独立
短章节」「没有上限」「不要因为感觉太长而跳过」），Fable 5 会当成进攻性目标
顶格执行——信息更全、专题更好读，但偏长、偏碎、摘抄偏密。

成本侧佐证：Fable 5 平均每天输出 token（含 thinking）约 2.0 万，比 Opus 4.6
的 3.0 万低 1/3——正文更长但 thinking 显著更短，说明它不需要靠反复叮嘱对齐。

### thinking 摩擦点（07/03–07/10 Fable 5 全量 + 3 份 Opus 对照）

1. **`token⟨原文⟩` 被误读为「文本损坏」**：07/04 thinking 把匿名器误触发的
   `⟨加一⟩` `⟨判断⟩` 当成 corruption 自创修复流程；「禁止 ⟨⟩」还被泛化成
   模糊的「避免特殊符号」自律（07/07、07/10），有误伤「」/`|`/`[[ref:]]` 的风险。
2. **每天从零论证要不要抽专题、叫什么名**：主线话题（Fable 发布、GPT-5.6、
   reset 卡）实际上天天存在；Opus 07/02 出现过五连改名马拉松。
3. **章节顺序每天重新纠结**（行业新闻 vs 方法论谁在前）。
4. **规则死锁**：「合并的唯一理由是对话连续」vs「不同议题拆开」——遇到
   一场连续对话跨多个角度时两头为难（07/07 thinking 明确点出矛盾）。
5. **blockquote 数字档位（0–4/6/8）诱发自我审计**，实际没有任何一天触到 8，
   反而系统性低于建议值。
6. **未覆盖场景**：撤回/删除消息的处理口径（07/07 模型自创）；
   「模糊化 / 章节不公开 / 公开」三态边界不清——10 天里 `[章节不公开]`
   零次使用，模型总是选「模糊化」回避判断。
7. system 与 user 消息里跨日规则重复两份（Opus 时代的保险，Fable 不需要）。

## 二、本次提示词调整（`wechat_daily/prompts.py`）

原则：**减少数量硬约束，给模型自由空间；单向鼓励改双向定性约束；只留一条红线。**

1. 「宁可多个独立短章节」→ 拆分与合并都以**议题**为准的双向表述；
   新增裁决规则：连续对话中议题切换时仍按议题拆节（解决死锁 §4）。
2. 「没有上限、不要怕长」→ 「两个方向的错误同样要避免」，
   唯一标准改为信息密度；删掉「15 个子话题合格」的数字锚。
3. blockquote 档位（0–4/6/8 三档）→ 只留「单节不超过 8 条」一条红线，
   其余交给「每条承担新信息」。
4. 专题触发条件（占比 1/3 + 3 个子话题的数字门槛）→ 「有明显主线默认抽专题，
   判断标准是重心而非占比」；明确主线常跨天延续，续日照常抽；
   例子补 `## GPT-5.6 实测第二日`。命名硬约束（4–10 字、禁描述句式）保留——
   实测执行完美。
5. 新增默认章节顺序：专题 → 行业新闻 → 工具 → 方法论 → 闲聊花絮，
   「自定」降级为例外。
6. `token⟨原文⟩`：显式合法化误触发场景（「这是预期内误报，按语义还原即可」）；
   ⟨⟩ 禁令严格限定为两个字符本身，点名「」/`>`/`|`/`[[ref:]]` 不受影响。
7. 新增撤回/删除消息处理规则（视同不愿传播）。
8. 「章节不公开」补三态边界：模糊化仅用于个别细节可泛化的场景；
   敏感点是核心时用不公开标记（群内版仍完整），禁止大面积模糊化回避判断。
9. 去重复：system prompt 里历史日报块的语义说明删掉，只留 `[[ref:]]` 语法与
   格式硬规则；去重/续写规则以 USER_INSTRUCTIONS 那份为准。
10. 导读要求补定性约束：「取舍不是缩写全文，短而有判断好过面面俱到」
    （不设字数硬指标）。

### 验证与回退

- 验证：观察接下来 3–5 天主版（Fable 5）+ 对比版（Opus 4.6）输出——
  预期 `###` 数量与行内摘抄密度回落、导读变短、其余质量指标不降。
- 回退条件：若出现漏话题回潮（对比版收了主版没收的实质话题）、
  或专题在无主线日被滥抽，恢复对应条目的数字门槛即可，改动彼此独立。

## 三、暂缓项（记录待做，按性价比排序）

### P0 | 花名册补 variants（`roster.py` / `aliases.py`）

thinking 里每天都在推断花名册外的稳定代称：「超哥」（风趣的企鹅）、
「然哥/陈然老师」（沉稳的仓鼠）、「谷哥」（稳重的海豚）、「课代表」等。
把已确认的外号/谐音/简称累积进花名册 variants，可省每日推理成本、
降低漏映射（=隐私泄漏）风险。可写脚本从历史 thinking/日报收割已确认映射。

### P0 | 匿名器误触发治理（`privacy.py`）

`⟨判断⟩` `⟨加一⟩` `⟨好好⟩`、把「尤其」「。。」当昵称——上游过度触发
留给模型收拾。方向：常见双字词白名单、昵称匹配最小长度/词频阈值、
已知产品名（DeepSeek 等）按上下文预判。提示词侧已缓解（§二.6），根治在管线。

### P1 | 重叠时段显式时间戳（`chat_extractor.py` / 输入拼装）

「首尾各约 1 小时重叠」目前靠模型自己推边界逐条核对。输入里直接标注
「与昨日报告重叠段：00:00–01:05」可省一段推理。

### P1 | 2026_05_06 文档遗留的三件未落地项

- **URL utm 清洗**（`renderer.py`）：公众号链接仍拖着
  `mpshare/scene/srcid/sharer_shareinfo` 长尾（07/10 日报可见）；
  `chksm/sn` 必须保留。纯程序，零 token 成本。
- **文末「延伸阅读」汇总**（`renderer.py`）：扫正文 `[标题](URL)` 自动生成，
  不经 LLM。
- **中文 slop 禁词/句式表**：对 Fable 5 建议精简执行——禁句式
  （三段式排比、总结尾巴）比禁词表更有效，且 Fable 5 当前输出 slop 不明显，
  优先级降低，出现回潮再加。

### P2 | `[[ref:]]` 目标清单

模型目前自己翻 previous_reports/titles 找引用目标，偶有引向只有标题的
早期日期、凭标题揣测的风险。可在输入里给「可引用章节标题 → 日期」清单。

### P2 | tag 词表

tag 仍自由生成，偶发 one-off（`glm-5.2` 点号 vs `glm-5-2`）。
维护 ~50 个高频标签词表注入提示词；与 2026_05_06 文档 P2-2 同源。
