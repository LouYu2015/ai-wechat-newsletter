# 2026-09-07 提示词第七轮微调：Opus 4.6 复位——松自审、治句式、重写导读

`design/2026_07_17_prompt_tuning_round4.md` 之后的第一次系统性复盘（第五、六轮
只有 commit message：`e3b95fb`、`46f5199`）。起因是 **08-07 的 `fa88bc8` 把主模型
从 Fable 5 换回 Opus 4.6**（旁路对比换成 Opus 5），而提示词还是七月为压制
Fable 5 冗长而层层加码的那一套，没跟着回调。

本轮由 Fable 5.1 做诊断与条款起草，用 **8 次离线重放调用**（非 batch，流式，

## 一、证据：抑制条款在 Opus 4.6 上过度生效

### 量化（14 天线上输出 08/23–09/05）

四条数字红线（段落 ≤5 句、点名 ≤3 人、单节行内「」≤4、导读一段 ≤200 字且
至多 3 个句号）**零违例**。代价是红线被当成了定额：

| 指标 | 6 月 Opus 4.6（旧提示词） | 7/14 Opus 4.6 对比版 | 08/23–09/05 线上 |
|---|---|---|---|
| 行内「」/篇 | 62–97 | 69 | **3–11** |
| 「」/100 条消息 | 13–30 | ~13 | **0.7–3.4** |
| 零引用节占比 | — | — | 36–67%（09/05：17 节里 14 节零「」） |

thinking 里能直接看到自审：「每节引号「」不超过 4 处……整理好这些限制后开始
撰写」「我要避免用「」直接引用原话，改成转述这个结论」，09/05 还花两段纠结
「blockquote 里的『Allow once』算不算行内摘抄配额」。

### 五月那份清单里的老问题一个都没解决，只是换了形态

- **导读模板化**：14 天里 13 天以「今天最值得读的是 / 最重磅的是 / 最大的看点是」
  起头，其中 9 天一字不差「今天最值得读的是……——」。SYSTEM_PROMPT 的 few-shot
  导读范例本身就是五月明令禁止的「X 分享了…Y 写了…」句式，示例与规则打架。
- **点名清单化**：以群友 token 开头的句子占 42–71%，最高频谓语是「分享了」
  （14 天 67 次）。点名配额只限人数不限句式，于是每段写成「A 分享了 X。
  B 补充 Y。C 感叹 Z。」正好卡在 ≤3 人。
- **形容词替代引语**：「传神」「炸裂」「令人瞠目」「真正让人拍案的是」；其中
  「传神」是提示词自身的词汇泄漏（原文出现 3 次）。破折号 2.3–5.8/千字。
- **tags 无分类价值**：14 天 200 个 tag，80% 只出现一次，多为章节标题缩写。

### 「至多 3 个句号」的反作用

09/05 导读把「维基劫持报告值得细读」和「NVIDIA 收购 HF 藏了彩蛋」两条不相干
线索用逗号焊进同一句——正是第六轮想禁的写法，被句号上限逼出来的。

## 三、本轮调整（`wechat_daily/prompts.py`）

1. **删自审措辞**：摘抄段的「按「」出现次数机械计数」「不存在『这条太短不算』
   的豁免」「每节写完回头数一遍」全部删除，红线独立成段并写明「红线只防极端
   情况，不是写作目标，写完不必回头清点」；补双向判据（「换成转述，读者会损失
   什么」「一节里有特色的话却一处「」都没有，通常说明摘抄不足」「有原话可摘的节
   通常保留 1–3 处」）。红线数字不变（行内 ≤4、blockquote ≤8）。
2. **新增叙述句式条**（与点名配额并列）：一段里以 token 开头的句子不超过一半；
   一人一句的排开写法改为以事件/观点做主语；同节第二次出现改用「他 / 她」；
   谓语不要反复用「分享了 / 贴出 / 表示」，能写态度的用态度动词。
3. **段落** 5 句上限 → 「一段只讲一个焦点，2–6 句」，并禁止一句一段的碎片化。
4. **导读整节重写**：删「至多 3 个句号」，改为「≤200 字、至多 4 句、不出现具体
   数字、一条线索一到两句」；要求编辑判断**说明理由**（落到对读者的意义）；
   新增「开头不要固定」——回看 `<previous_reports>` 避免与前几天同一种开头，
   给四种可轮换的开头范式。SYSTEM 侧只留「一个自然段」，数字不再重复两份。
5. **few-shot 导读范例**换成非模板句式（原范例正是五月禁止的「X 分享了…」）。
6. **新增用词与标点条**：禁评价性形容词表（含提示词自身泄漏的「传神」，摘抄
   门槛的「更传神」同步改为「更有特色」）、禁「最炸裂的是」类抬升句式、
   破折号每节至多 1 处。
7. **tags**：5–8 个、可跨日复用的主题词、优先复用 `<previous_reports>` 里出现过
   的标签，不造章节标题缩写式的一次性组合。
8. **隐私专项新增「内部配额、流程与制度同属内部信息」**：团队 AI 工具月度额度、
   内部 RCA / 事故处理工作流、内部工具使用政策、考核与绩效规定——即便内容中性、
   技术性强，发言者写「某群友」；只谈通用技术方案、不涉及本公司具体制度与数据的
   正常署名。
9. **结构清理**：SYSTEM 首段自我描述改为与实际相符（它还规定引用规则、跨日引用
   语法、隐私规则）；「关于图片」末尾的孤句并入导读要求。

**评估后未采纳**：跨日衔接条（同一 ref 只引一次、少用「延续」）与「归属两可任选
其一」——三天重放中无可测效果，不进正文以免继续膨胀。

## 四、验证计划与回退条件

按 7 天滚动均值看（单日噪声大，尤其句式与摘抄两项）：

| 指标 | 目标 | 回退条件 |
|---|---|---|
| token 开头句占比 | <50%（基线 55%） | 抽读发现「谁说的」不清 → 「不超过一半」放宽为「不超过三分之二」 |
| 「分享/贴出/表示」 | ≤6/天 | — |
| ——/千字 | ≤3 | 出现生硬断句 → 删破折号条，保留形容词条 |
| 评价性形容词 | ≤1/天 | — |
| 导读 | ≤200 字、≤4 句、量值数字 0（型号名不计）、7 天内前 8 字相同开头 ≤2 | 连续 3 天 >200 字 → 恢复「至多 3 个句号」；被写秃（线索 <2 或无理由句）→ 去掉「不出现具体数字」 |
| 行内「」 | 不设目标；零引用节 <50%、单节 ≤4 | 单节 >4 连续 3 天 → 删「通常保留 1–3 处」一句 |
| 段落 | 1 句段 <10%、>6 句段 ≤1/天、>300 字墙段 0 | 墙段 >2/天 → 上限改回 5 句 |
| tags | 5–8/天；14 天 one-off 比例 <50%（基线 80%） | — |
| 覆盖 | `###` 与 14 天中位（15）差 ≤3 | 连续 3 天少 ≥4 节 → 检查段落条是否导致过度合并 |
| output tokens | 均值 ≤46k | 连续 5 天 >55k → 删导读「说明理由」一句 |
| 隐私 | 「某群友」1–5/天为预期；`[章节不公开]` 月度回看 | 技术架构节被整体去名（内容删除而非换署名）→ 条款补「技术方案本身不算内部制度」 |
| 格式红线 | ref / tags / ⟨⟩ / 专题命名 / 闲聊花絮末位零违例 | 任一违例 → 单独回滚对应条 |

**注意**：以上数字全部只对 Opus 4.6 有效。旁路 Opus 5 在这套提示词下的行为尚无
数据；若要换主模型，先跑一次同样的离线 A/B。

## 五、暂缓项（程序层，按性价比）

1. **匿名器误触发**已到影响语义的程度：09/05 一条消息被改成「乐观的喜鹊⟨唯一⟩
   的问题是……坚定的蜂鸟⟨测试⟩没做……淡定的水獭⟨加一⟩句 prompt」——「唯一 /
   测试 / 加一 / 结果 / 好的 / 尤其」都是花名册里的真实昵称，需要最小长度与
   停用词表（`privacy.py`）。
2. **引用行残留未匿名化真名**：`> 引用 JEROME:`（`message_parser.py`）。
3. **tags 词表注入 + 后处理归一化**（与 2026_07_13 文档 P2 同源）。
4. **batch 请求打 cache_control**：`debug/costs.jsonl` 里 `cache_read` 长期为 0。
5. **红线数字按模型参数化**：`config.py` 已有 per-model 表，把行内「」/blockquote/
   点名/导读字数做成参数，避免下次换模型再来一轮全文改写。
